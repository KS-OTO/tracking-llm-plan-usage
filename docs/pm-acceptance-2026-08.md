## 遗留与建议

1. **账号错误文案映射漏配**（#11，低）：`ACCOUNT_ERROR_HINTS` 按子串匹配，阿里云实际返回「This API is not authorized for caller.」（含空格大小写）匹配不到 `NotAuthorized`，建议在 server/aliyun.ts 将上游 Code 透传为错误码而非仅 message（app.ts:221 已取 `body.Code`，但该响应 Code 为空），或增加不区分大小写的归一化匹配。
2. **bun 静态服务下主题按钮渲染异常（未定性）**（#18，低，待人工复核）：8791（Bun.serve dist）长驻无头标签页中，header 主题按钮位显示为永久 loading 的主色图标按钮且无 aria；同字节经 vite preview（5198）正常、Pinia store `loading=false` 与按钮态自相矛盾，倾向长会话标签页残留而非产品缺陷。建议人工在浏览器开 `bun run server` 复核一次；另建议 Bun 静态响应补 `Cache-Control`/`ETag` 头（当前无缓存头，vite preview 有 `no-cache`），降低陈旧资源风险。
3. **别名未在真实环境使用**（#8，提示）：.env 尚无任何 `*_LABEL`，建议为多账号（模力方舟×2）补别名以实际受益。
4. **预警行跳转目标粗粒度**（#6，低）：OverviewTab.vue:337-341 预警行跳转仅区分智谱/火山两档，火山 Coding 窗口与 Agent Plan 窗口同落 `volc-plan`，多账号时无法定位到具体账号子卡；可后续为子卡加账号级锚点。
5. **测试补强**：`multi.test.ts` 尚未覆盖本轮新增的 `readPairedMap`/`readIncompletePairs`（label 与 incomplete 链路目前靠 e2e/手工验证）；e2e 中导航卡跳转用例因密封环境无数据被 skip（dashboard.spec.ts:40-42），建议增加 mock 数据版用例。
