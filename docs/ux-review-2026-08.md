### 场景①：早上扫一眼哪些号快用完 —— 「看起来健康」≠ 健康

预警数据源只有两处：火山 Agent/Coding 窗口（`src/components/OverviewTab.vue:49-84`）和智谱 Coding Plan 窗口（`OverviewTab.vue:85-100`）。也就是说：

- DeepSeek / 模力方舟余额不足、阿里 Token Plan 座席或 CREDITS 耗尽、代金券到期——**全部不进预警**。用户以为"无 ≥70% 的额度窗口"（`OverviewTab.vue:363`）就是全线健康，实际是预警雷达只扫了两家。
- 阈值 70/90 硬编码（`OverviewTab.vue:56`、`OverviewTab.vue:104`），多号玩家的号有主次之分，无法按号设阈值。
- 预警列表截断 8 条（`OverviewTab.vue:332`），溢出仅一句"还有 N 项，点击任一行跳转详情"（`OverviewTab.vue:359-361`），**没有展开入口**——用户永远看不到第 9 条之后的预警。

**实测断链（最严重）**：本机阿里云账号查询失败（`This API is not authorized for caller.`）时，总览导航卡数组由 `okAccounts()` 过滤失败账号（`OverviewTab.vue:256-267`），阿里卡**整张消失**（实测 5 张导航卡无阿里资源包）；而头部 provider 标签仍显示绿色「阿里云 ×1」（来自 `/api/status` 的配置状态，`src/App.vue:134-144`，status 不感知账号查询失败）。两个信号互相矛盾：配置了 1 个号、总览却查无此平台。用户无法区分「没配」「配了但失败」「配了且为空」。

**Token Plan 卡的误导**：实测显示「阿里 Token Plan 0 座席 剩 0 CREDITS」——座席为 0 与查询异常在导航卡上是同一个呈现（`OverviewTab.vue:208-216` 无 danger/异常标记）。

### 场景②：对比各平台余额 —— 没有对比，只有巡视

- 余额 Tab 实测总高 3156px（视口 900px），4 个区块（智谱 157px 处、DeepSeek 987px、阿里 1323px、模力方舟 1593px 起）纵向排布，对比 = 滚动 + 记忆 + 心算。
- 总览导航卡只有 DeepSeek / 模力方舟带金额（`OverviewTab.vue:225-253`）；智谱卡显示的是套餐档位与用量百分比（`OverviewTab.vue:186-195`），阿里卡显示"N 个包"。**跨平台资产没有统一口径的呈现位置**。
- 单位不统一：CNY、CREDITS、代金券、包数混排，无换算无标注。
- 智谱余额从总览出发：导航卡跳到的是「套餐订阅」Tab 的 plan 锚点（`OverviewTab.vue:190`），要看余额需再切「余额账户」Tab 再滚动寻找——同一平台两个入口分居两个 Tab（`src/App.vue:173-181` vs `src/App.vue:195-203`），心智模型割裂。

### 场景③：查某平台详情 —— 跳转概念好，落点被 header 吃掉

导航卡点击 → `jumpToAnchor` 切 Tab + 双 rAF 后 `scrollIntoView({block:'start'})` + 锚点闪烁（`src/App.vue:43-55`）。交互设计本身是亮点。但实测（1440×900）：

- `scrollIntoView` 后锚点元素顶边在视口 y=0，而 sticky header 底边在 y=89——**目标卡片的标题区整段被盖住 89px**，卡片标题不可见（实测 `coveredPx: 89`）。代码未给锚点设 `scroll-margin-top`，闪烁描边（`src/App.vue:321-325`）也被遮一半。用户跳转后必须先向上校滚一次才能看到"这是哪张卡"。
- 跳转实现用双 `requestAnimationFrame`（`src/App.vue:45-47`）：实测隐藏页/节流场景下 rAF 完全不触发（headless 中 `flashed:false`、scrollIntoView 从未被调用），依赖渲染帧时序而非 Vue 的 `nextTick`，属于脆弱实现——弱设备、后台标签页回切等场景有跳转丢失风险。
- 预警行点击的死代码：`alert.platform.includes('Coding') ? 'subscription' : 'subscription'` 两个分支相同（`OverviewTab.vue:339`）；且 Enter 处理器（`OverviewTab.vue:343-345`）与 click 处理器逻辑不同步（Coding 分支缺失，当前恰好无害）。
- 详情页无「返回总览」affordance：只能再点 Tab；切 Tab 后滚动位置被浏览器钳制而非归位（实测余额 Tab 滚 2000px → 切总览后 scrollY=32），落点不可预期。
- Tab 状态不进 URL（`activeTab` 是纯 ref，`src/App.vue:40`）：刷新丢位置、无法把「余额账户」Tab 分享给别人、无深链。

### 场景④：发现异常查原因 —— 恢复闭环不通

- **账号级失败**（实测阿里 LTAI****ogsf）：失败账号卡内展示 `t-alert` 错误横幅（`src/components/VolcPlanSection.vue:106-112` 等各 Section 同构），但错误是供应商原文英文（"This API is not authorized for caller."），无翻译、无处置建议、无该账号单独重试按钮——重试只能点头部全局刷新，把 9 个接口全部重打。
- **后端断连**：错误文案硬编码「无法连接后端 API 服务（127.0.0.1:8787）」（`src/api.ts:47-51`）。实测服务跑在 8794，文案仍在说 8787——排障时误导用户去检查错误端口。且该文案会在 9 个区块各出现一次，没有全局聚合（头部/总览均无，`headerAlerts: 0` 实测）。
- **部分失败的静默与自愈**：实测屏蔽 deepseek 接口后刷新——仅对应区块内出现横幅，总览与头部零信号；60s 后自动刷新成功，横幅消失且**无「已恢复」通知**。期间 `lastUpdated` 因"至少一路成功"照常前进（`src/stores/dashboard.ts:123-126`），时间戳对失败分片说了谎。
- 唯一设计良好的恢复语义：刷新失败保留旧数据 + 横幅置顶不闪断（`src/components/AccountSection.vue:34-37`、`src/stores/dashboard.ts:4-5`），以及 `NOT_CONFIGURED` 中性空态而非红色报错（`dashboard.ts:27-28`、`AccountSection.vue:30-32`）。

## 二、信息架构诊断

### 四 Tab 分组 vs 用户心智

| Tab      | 内容                                                      | 心智匹配问题                                                                                               |
| -------- | --------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| 总览     | 预警 + 重置 + 平台导航卡                                  | ✓ 合理，是全站入口                                                                                         |
| 套餐订阅 | 火山 Agent Plan、火山推理用量、智谱 Plan、阿里 Token Plan | 「推理用量」是用量明细而非订阅（`src/App.vue:163-172`）；阿里 Token Plan 与余额 Tab 的阿里资源包同凭据分家 |
| 余额账户 | 智谱余额、DeepSeek、阿里资源包、模力方舟                  | 智谱在两个 Tab 各出现一次（`App.vue:173` vs `App.vue:195`），用户按平台找数据时被拆散                      |
| 扩展平台 | 6 家杂项余额                                              | ✓ 合理（低频收纳）                                                                                         |

核心问题：**分组维度是"数据形状"（订阅/余额），用户心智是"平台"**。四场景中三个（②③④）都以平台为主键，现状却要求用户记住"智谱的余额在余额 Tab、套餐在订阅 Tab、用量在订阅 Tab"。头部 provider 标签行（`src/App.vue:134-144`）已经是按平台组织的——但它只是展示，不可点击。

### 预警 → 详情 → 恢复闭环

- 预警 → 详情：✓ 通（预警行/导航卡可跳锚点，唯落点被 header 遮挡，见场景③）。
- 详情 → 恢复：✗ 断。无单区块/单账号重试；错误无处置指引；恢复无通知。
- 恢复 → 预警：部分通。自动刷新 60s 会重算预警（`dashboard.ts:31,149-153`），但预警阈值/范围缺口（场景①）使闭环覆盖不全。

## 四、效率工具缺口

已有的：锚点跳转（导航卡/预警行）、`t-back-top`、模型过滤输入框、`clearable`。

缺口（按影响排序）：

1. **`t-back-top` 实测永不出现**：滚动 2200px 时仍 `opacity:0; visibility:hidden`。TDesign 1.20.6 默认 `container:"body"`（`node_modules/tdesign-vue-next/es/back-top/props.mjs`），而本页滚动体是 `documentElement`（实测 `body.scrollTop=0` 而 `window.scrollY=2200`）——监听挂错容器，长页唯一的返顶工具是死的。修复：`:container="() => document.documentElement"`（或升级后验证默认行为）。
2. **无全局搜索**：多号玩家"我的某个号在哪个平台"没有检索入口，只能逐 Tab 扫 keyHint。
3. **Tab 状态不进 URL**（见场景③），无深链、无刷新保位。
4. **时间范围不可切换**：火山明细固定 7 天（`dashboard.ts:33` `VOLC_DETAILS_DAYS = 7`），无法看 30 天趋势。
5. **provider 标签行不可点击**（`App.vue:134-144`）：按平台组织的天然快捷入口被浪费。
6. **表格无排序**：明细表列定义均无 `sorter`（`VolcPlanSection.vue:40-45`、`VolcUsageSection.vue:21-27`），"哪个模型吃得最多"要肉眼扫。
7. **无区块折叠**：多账号时套餐 Tab 单账号就含 4 窗口 + Coding 窗口 + 明细表（`VolcPlanSection.vue:115-219`），全部摊开。
8. **无键盘快捷键**：R 刷新、数字键切 Tab 这类高频操作无快捷方式。

## 六、P0：主题切换按钮加载后自毁（实测复现 + 根因定位）

**症状**：进站 0.8s 时头部主题按钮正常（`theme-default / variant-outline / aria-label=切换为浅色模式`）；约 2.5s 后（首次数据刷新成功、`.last-updated` 文本出现的同一帧）该按钮变成 `t-is-loading` 永久 spinner、`aria-disabled="true"`、类变为 `theme-primary variant-base`、aria-label 消失、图标被 spinner 替换——**此后无法点击，暗色↔浅色切换彻底失效**。

**证据链**：

1. 干净重载后 t0–t+2s 按钮健康（theme=default，aria=true）；t+2.5s `.last-updated` span 出现，**同帧**按钮损坏（theme=primary，loading=true，aria=false）。
2. 用 CDP 屏蔽全部 `/api/*` 重载（loading 状态照常翻转、但 `lastUpdated` 永远为 null、span 不出现）：4s 后按钮**保持健康**——排除网络失败/loading 翻转，锁定触发者是 `<span v-if="lastUpdatedText">` 在 `<t-space>` 内的挂载（`src/App.vue:110`、包裹层 `App.vue:109-132`）。
3. 损坏后实测点击无效（TDesign Button 在 loading 态吞掉 click）。

**定性**：TDesign 1.20.6 `t-space` 在条件子节点插入导致兄弟 `t-button`（icon-only）vnode 属性错乱的渲染缺陷，被本应用的 `v-if="lastUpdatedText"` 触发。

**修复方向（组件级，非"调 CSS"）**：

- 首选：把该 span 改为常驻节点（`更新于 --` 占位，仅内容变化），消除 t-space 子列表结构变化；或将其移出 `t-space` 单独布局；
- 或去掉 `t-space`，改用一行 `t-flex`/头部布局容器承载这组控件；
- 加回归用例：刷新成功后断言主题按钮可点击且带 aria-label（现有 `src/__tests__/` 已有挂载基建可复用）。

## 八、结语

这份仪表盘的交互底盘比大多数同类项目扎实：锚点跳转 + 闪烁定位、错误不闪断、NOT_CONFIGURED 中性空态、防抖局部刷新，都是正确的设计决策。但它现在输在三个系统层面：

1. **闭环不完整**——预警只扫一半平台、失败平台静默蒸发、错误无重试无恢复通知，「发现异常→定位→恢复」的链条每段都缺一口气；
2. **两个实测失效的交互件**——主题按钮自毁（P0-1，根因已定位到 `v-if` span 触发 t-space 重渲染）与返顶按钮永不出现，都是"看起来有、用起来无"的信任杀手；
3. **平台维度与数据形状维度的错位**——四 Tab 按"订阅/余额"切，用户按"平台"找。

优先把 P0 的五项修掉（其中 1、2 是纯缺陷，3 是一行定位修正，4、5 是信息架构补洞），总览的"可信度"会立刻上一个台阶；P1 的预警扩面 + 余额对比表则直接回应高频场景①②的核心诉求。
