## 三、新发现

1. **[P0·阻塞终审] 请求级失败时平台卡静默蒸发（④）**
   - 现象：abort `/api/deepseek/balance` 刷新后，总览导航卡 6→5，DeepSeek 卡消失（应显示「查询失败」danger 卡）。
   - 根因：`OverviewTab.vue` summaries 各平台出卡守卫 `if (xxAll.length > 0)`（如 DeepSeek :242、火山 :163、阿里 :287 等）——请求失败时 `data=null` → `xxAll=[]` → 整段跳过，未检查 `slice.error`。账号级失败（响应 200 但账号全错）路径已正确（阿里资源包实测出卡）。
   - 修复面小：出卡守卫前补 `slice.error` 判断并 `push(查询失败卡)`；横幅（App.vue `failedProviders`）已正确覆盖该场景，无需改动。
2. **[P1] 手写数字样式清理不彻底（⑦）**
   - `.nav-primary` 16px/600（`OverviewTab.vue:505-510`）为 UI 审查 P0-4 明令删除项，仍以硬编码 px/字重存在（6 处导航卡主数字）；`.reset-countdown` 类名残留（样式已删，渲染退化为 14px/400 正文级，「最近重置」数值失去强调层级）；`resetDisplayValue()`（:333-341）为未接线的死代码。
   - 建议：`nav-primary` 改 token（`--td-font-size-title-medium` + medium 字族）或 t-statistic 小号；删除死代码与残留类名。
3. **[观察] 计量陷阱**：t-switch 选中类是 `t-is-checked`；t-list 行是 `li.t-list-item`（非 `.t-list__item`）；back-top 可见性类是 `t-back-top--show`——自动化断言勿用错误选择器（本轮曾因此误判，已更正）。
4. **[观察] 总览页高 1077px（900 视口）不足 back-top 阈值——功能非缺陷；套餐页 3275px 验证通过。**
