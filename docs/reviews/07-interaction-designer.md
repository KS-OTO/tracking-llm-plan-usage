# 交互设计师 审查报告

## 审查范围与视角

以**交互设计师 / 可达性工程师**视角，对全栈全流程进行红蓝对抗审查，重点关注：

- **屏效与信息层级**：单列布局锁定、多区块无分组无导航、表格固定高度、桌面留白。
- **状态反馈**：loading / error / 空状态 / 刷新 / 过滤的反馈质量与一致性。
- **交互流程**：自动刷新、多账号分隔、进度条阈值、倒计时文案边界、单点重试。
- **可达性与适老化**：landmark、焦点管理、对比度、字号缩放、键盘可达、色彩冗余。
- **暗色模式**：token 接入、持久化、跟随系统。

取证来源：`src/App.vue`、`src/components/*.vue`、`src/assets/main.css`、`src/utils.ts`、`src/types.ts`、`index.html`、`src/main.ts`。所有结论均附文件:行定位。

> 基线认知：当前前端使用 **tdesign-mobile-vue**（移动端组件库），整页按移动端单列设计，这是下文诸多桌面端体验问题的根因，也是用户计划迁移到 tdesign-vue-next（桌面端）的动机。本报告同时记录迁移前后均应修正的交互缺陷。

## 总结与优先级建议

### 必须在迁移中一并解决（P1，阻塞体验）

1. **暗色模式 + 适老化基础**（`main.css:8` color-scheme、对比度、字号）：当前完全缺失，迁移桌面端是引入 dark token 与可达性基线的最佳时机。
2. **刷新/过滤的反馈与防抖**（`App.vue:133-136` 无防抖+全量请求、`App.vue:184-207` 后续刷新无反馈）：这是当前最严重的**功能性交互缺陷**——输入过滤触发 9 接口风暴且无 loading 反馈，应优先修正为单接口 + 防抖 + 行内 loading。
3. **屏效与信息架构**（720px 锁死、8 区块无分组无导航无折叠）：迁移桌面端的核心目标，需重设响应式多列 + 锚点导航 + 折叠。
4. **语义化与可达性地基**（landmark/skip link/lang/title/focus-visible/reduced-motion）：低成本高收益，应在迁移骨架阶段落地。

### 重要改进（P2，影响可用性与一致性）

5. **错误反馈与单点重试**：cell note 过弱，需 Result/Alert + 分级 + 单区块重试。
6. **自动刷新体验闭环**：可见标签 + 倒计时 + 页面可见性感知 + 周期可调 + 状态持久化 + 重入保护。
7. **去重与统一**：删除死代码 `SectionCard.vue`、统一 `windowStatus`、修正重复百分比、统一空状态与行 key。
8. **倒计时与表格高度**：倒计时实时化 + 文案分档；表格高度响应化、消除双层滚动。

### 细节打磨（P3）

9. 阈值依据文档化、provider-tags 色彩冗余、零数据空状态、字号 rem 化等。

### 与迁移路线的耦合建议

- **tdesign-mobile-vue → tdesign-vue-next 不是简单替换组件名**：应借迁移重建信息架构（分组/导航/折叠/响应式多列）、引入 dark token、落地可达性基线，并修正上述刷新/过滤/反馈逻辑——否则只是把移动端缺陷原样搬到桌面端。
- 死代码 `SectionCard.vue`（异种 token 体系）应在迁移前清除，避免污染新设计系统。
