# 产品经理 审查报告

## 审查范围与视角

从**产品价值 / 用户旅程 / 信息架构 / 文案与心智模型**四个维度，对全栈全流程做只读审查。重点回答本次重构前的关键问题：

- 9 类数据源区块的分组、排序、屏效是否合理；
- 首次打开（无任何 key）、配置 key 后、多账号、刷新 / 自动刷新 / 模型过滤等核心旅程是否顺畅；
- 标题 / 副标题 / 单位（CNY / USD / Tokens / credits）是否清晰，错误文案对非技术用户是否友好；
- 缺失哪些常被期待的能力。

取证来源：`src/App.vue`、`src/components/*.vue`（8 个区块 + `SectionCard`）、`src/api.ts`、`src/types.ts`、`src/utils.ts`、`src/assets/main.css`、`server/app.ts`、`server/multi.ts`、`index.html`、`README.md`。

> 说明：区块组件实际为 8 个（火山方舟拆成 `VolcPlanSection` + `VolcUsageSection` 两个），加上扩展平台内含 6 家子平台，故数据源口径为「9 类」。

## 总结与优先级建议

### 必须在重构中解决（P1，影响核心旅程与心智模型）

1. **模型过滤改为防抖 + 局部刷新**（`App.vue:133-136`）—— 当前是真实可用性缺陷，打字即全量重发，重构桌面端时务必修正。
2. **首屏空态 / onboarding**（`App.vue` + 全部 section）—— 把「无 key = 错误墙」改为引导卡，是新用户留存的第一道关。
3. **半配置静默丢弃**（`multi.ts:51-56`）—— 补结构化提示，消除「我配了为什么说没配」的困惑。
4. **Token Plan 单位缺失**（`TokenPlanSection.vue`）—— 明确 CREDITS 单位，消除 token/元混淆。
5. **按账号错误的中文友好化**（`app.ts:139` + 各组件）—— 把顶层已有的 `ERROR_HINTS` 能力下沉到 per-account。

### 应在重构中一并修正（P2，信息架构与一致性）

6. **概览标签栏 / footer / status 接口三处口径对齐**，补齐 Token Plan 与扩展平台。
7. **`SectionCard` 统一外壳 + 副标题**，删除死代码，恢复 subtitle 心智锚点。
8. **顶层分组 / Tab / 摘要区**，把监控工具「一眼看异常」的价值做出来。
9. **后台标签页暂停轮询、金额单位统一格式化、单板块重试、浏览器标题与 lang 修正。**

### 细节打磨（P3）

10. README 首段范围、页面副标题、术语统一（账号 vs 凭据）、Coding Plan 窗口 meta 冗余、刷新间隔可配置。

### 重构方向建议（PM 视角）

- **信息架构**：顶层从「平铺 8 卡」升级为「摘要条 + Tab 分组（余额 / 套餐额度 / 资源包）」，桌面端 `max-width:720px` 的移动端约束应随本次迁移到 `tdesign-vue-next` 一并放开，充分利用宽屏做多列 / 并排对比。
- **用户旅程**：补「首启引导 → 配置反馈 → 异常一眼可见 → 单点重试」闭环，而非全有或全无的批量刷新。
- **心智模型**：统一单位与术语，让副标题成为每个板块的「一句话说明书」。
