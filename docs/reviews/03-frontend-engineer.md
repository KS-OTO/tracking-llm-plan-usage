## 总结与优先级建议

### 核心问题

本次审查发现的最严重问题是 **P0 级 token 引用错误**：`main.css` 使用了 `tdesign-mobile-vue` 中不存在的 `--td-radius-medium` token，导致所有 `.window-card` 和 `.balance-cell` 渲染为无圆角——这是一个已经存在于生产环境的可见视觉缺陷，但很可能被开发者误认为是"设计如此"。

### 按优先级排序的修复建议

1. **立即修复（P0）**：将 `--td-radius-medium` 替换为存在的 token（`--td-radius-default` 或 `--td-radius-large`），恢复卡片圆角。

2. **迁移前必须解决（P1）**：
   - 模型过滤防抖 + 精准刷新（避免 9 接口连带刷新）
   - `totalsOf` 重复计算（改 computed 缓存）
   - 刷新失败不覆盖旧数据的 UX 修复
   - 删除 SectionCard 死代码
   - 修复 `index.html` 的 `lang` 和 `<title>`
   - 确认 tdesign-vue-next 迁移方案（本次审查确认了移动端组件库在桌面端的屏效问题根因）

3. **迁移过程中一并解决（P2）**：
   - 去掉 `max-width: 720px` 锁死，引入响应式多列布局
   - 激活暗色模式（库已支持，只需添加切换逻辑）
   - 消除手写 CSS 泛滥，统一用 TDesign 组件 + token
   - 全量 import 改按需导入
   - 合并重复的标签映射
   - 适老化字号（rem 化）
   - 修复 `api.ts` 硬编码地址

4. **代码质量打磨（P3）**：类型安全改进、命名常量、模板内联处理器提取、columns 定义风格统一等，建议在迁移重构中顺带处理。

### 迁移到 tdesign-vue-next 的注意事项

当前代码与 tdesign-vue-next 的主要差异点：

- 组件名前缀不变（`t-*`），但 `t-cell-group`/`t-cell` 应替换为 `t-table`/`t-card`/`t-descriptions` 等桌面组件
- token 命名空间同为 `--td-*`，但具体值不同（桌面端 radius/spacing 更紧凑）
- `t-navbar`（移动）→ `t-head-menu` 或 `t-layout`（桌面）
- 按需导入方式一致，可用 `unplugin-vue-components` 自动引入
- 暗色模式切换机制相同（`.dark` 类 / `theme-mode` 属性）
